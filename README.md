# Mihomo Manager

基于 Linux 的 Mihomo Web UI 管理器。面向可信局域网中的单用户使用，将配置文件、订阅、代理集合、规则与运行状态放在同一个桌面／移动端界面中管理。

管理器使用 Mihomo 原始 Controller API 处理运行操作，并以独立服务保存配置与管理器设置。当前正式版本为 **0.2.1**；[GitHub Releases](https://github.com/buluw/mihomo-manager/releases) 提供程序包、对应源码及 SHA256。具体源码身份与运行要求见包内 `RUNTIME_BUILD.json` 和 `SOURCE_METADATA.json`。

## 功能

- **配置中心**：管理多份命名配置，支持新建、上传、重命名、删除、YAML 编辑、格式化和自动换行；可以查看只读运行配置。
- **订阅与节点整合**：导入及定时更新 Clash/Mihomo YAML 订阅，从订阅或本地配置提取代理集合，配置节点过滤，并在源配置中组合使用。定时更新由服务端执行。
- **代理与集合**：选择代理、测试延迟、触发集合健康检查、查看节点信息；自动或人工合并同一节点的显示项，维护人工地区。显示合并与地区设置只影响管理器呈现。
- **规则管理**：编辑源配置的主规则、调整顺序与策略，管理代理集合／规则集合文件及其引用。普通 File 集合可以编辑；HTTP 缓存和自动提取正文保持由对应来源维护。
- **运行监控**：查看流量、连接、日志、网卡信息，以及固定项目服务的状态、内存与受控目录磁盘占用。
- **持久设置**：编辑常规、DNS、TUN 与出口、嗅探设置。管理器覆盖值写入独立 JSON，生成独立运行 YAML，源配置保持可编辑。
- **访问认证**：独立的访问密码与会话管理，支持开启、关闭、改密和退出。会话失效时保留页面上的未保存草稿，重新登录后继续操作。
- **Web UI 更新**：查询正式发布、下载或上传运行包，独立校验、确认安装与本地回退；支持持久后台检查、自动下载和按容器时区定时安装。
- **Core 维护**：在“更新与维护”中检查官方版本，下载或上传并校验核心，确认安装，以及回退到保留的上一版本；支持固定 Core 服务的手动启动／重启。

### 保存与应用

“保存配置”保存磁盘中的源文件及可写集合草稿。改变 Core 运行内容时，需要明确执行“应用配置／切换配置”；管理器生成运行文件，由前端调用 Controller 加载，再记录成功结果。加载失败时，磁盘配置与正在运行的配置可能不同。

最近成功加载记录是共享操作记录。无法可靠确认运行来源时，界面会显示未知。节点显示合并也不会改写 Mihomo 节点或自动合并多份完整 YAML。

## 安装

当前验证平台为 **Debian 12 x86_64、systemd、Nginx、Node.js 24.15.0**。源码安装入口会准备固定服务及目录，适合独立的 Debian 主机、虚拟机或已配置好权限的容器。

- [Linux 安装、目录与服务说明](docs/user/installation.md)
- [配置、订阅与维护使用说明](docs/user/usage.md)
- [0.2.1 发布说明](docs/user/release-notes.md)
- [源码导出与发行包构建](release/README.md)

运行包包含前端和 configd、logd、sysinfo 三个管理服务的编译产物、必要依赖与部署文件。Node.js、Nginx 和 Mihomo Core 由宿主环境单独提供；运行包适用于已由本项目部署入口管理的环境，首次安装使用源码入口。

网站默认监听 `0.0.0.0:9090`，后端接口监听回环地址。首次安装的引导配置只启用回环代理端口，TUN 和 DNS 接管由用户按网络方案配置。访问认证初始为关闭，建议在“访问认证”中设置密码。HTTP 部署需要可信的访问网络；跨越不可信网络时，应配置 HTTPS 入口并控制网络访问。

Web UI 在线更新由独立安装任务完成，按变更重启管理器服务，保留 Core 代理运行和用户数据。正式发布不可用时如实提示，仍可上传受信任的兼容运行包。CT 模板与一键创建 CT 单独提供时会在安装文档中说明。

## 开发与验证

四个组件各自维护 `package.json` 与锁文件。在 Node.js 24 环境中分别运行 `npm ci`、`npm run lint`、`npm test` 和 `npm run build`。Linux 构建产物由运行包流程统一汇集。

前端开发服务器通过 `MIHOMO_GATEWAY_TARGET` 指向已有的同源认证网关；默认是 `http://127.0.0.1:9090`。`frontend/` 为正式前端，`configd/` 负责配置持久化，`logd/` 负责日志采集，`sysinfo/` 负责系统只读信息、访问认证、受限 Core 维护以及独立的 Web UI 更新与后台策略。
